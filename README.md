# Город для всех — модуль сбора данных (MVP)

Это приложение для волонтёров: открываешь карту, выбираешь точку, вносишь данные
о дорожном объекте (съезд / переход / дорога). Собранные данные — основа базы,
по которой потом строятся маршруты для людей с ОВЗ.

Этот документ объясняет **что внутри** и **как запустить**, с нуля и по-человечески.

---

## 1. Как запустить (быстрый старт)

Нужен установленный **Node.js** (версия 18 или новее). Проверить: `node -v`.
Если Node нет — скачай с https://nodejs.org (бери LTS-версию).

Дальше три команды в терминале, из папки проекта:

```bash
npm install     # 1) скачать зависимости (один раз). Создаст папку node_modules.
npm run dev     # 2) запустить в режиме разработки
```

После `npm run dev` в терминале появится адрес вроде `http://localhost:5173`.
Открой его в браузере — увидишь карту. Кликни по любой точке → внизу появится
карточка с координатами → кнопка «Добавить» → откроется панель ввода данных.

Чтобы остановить — `Ctrl+C` в терминале.

Другие команды:

```bash
npm run build       # собрать готовую версию в папку dist/ (для выкладки на сервер)
npm run typecheck   # проверить типы без запуска (полезно перед коммитом)
```

## 2. Что уже работает, а что нет

**Работает:**
- Карта (Leaflet + OpenStreetMap), выбор точки кликом, координаты.
- Панель ввода с тремя типами объектов (съезд / переход / дорога), один за раз.
- Выпадающие списки наполняются из справочников.
- Условные поля: показываются серыми, пока не выполнено условие (например, ширина
  съезда активна только когда отмечен «съезд на проезжую часть»).
- Проверка ввода (число не число, пустое поле) с понятными сообщениями.
- Сбор всех данных по кнопке «Сохранить».

**Намеренно НЕ подключено (ждёт следующего этапа):**
- **Отправка на сервер.** По «Сохранить» данные пока только показываются на
  экране, а не уходят на бэкенд. Место подключения помечено в коде комментарием
  `ТОЧКА ПОДКЛЮЧЕНИЯ ОТПРАВКИ` (файл `src/ui/app.ts`).
- **Справочники берутся из заглушки** (mock), потому что бэкенда ещё нет. Данные
  лежат в `src/mock/mock-dictionaries.ts`. Когда появится настоящий сервер —
  замена в одну строку (см. раздел 5).
- **Адрес по координатам** (обратное геокодирование) — показываем только
  координаты, место под адрес помечено `TODO` в `src/ui/map/map-screen.ts`.

## 3. Структура проекта

Проект организован **по фиче, а не по слою**: всё про съезд лежит в одной папке,
всё про переход — в другой. Так модуль самодостаточен, и новую сущность добавляешь
копированием папки, а не размазыванием по десяти местам.

```
src/
  shared/                  ← общий фундамент, используется всеми
    result/                  Result<T,E> — ошибки без исключений
    parsing/                 строка формы → число/bool (с проверками)
    http/                    HttpClient + договор IHttpClient
    dictionary/              DictionaryService — справочники (текст ↔ id, кэш)

  features/                ← бизнес-логика, по одной папке на тип объекта
    ramp/                    СЪЕЗД — эталонная фича (образец для остальных)
      ramp.entity.ts           модель данных + тип ввода формы
      ramp.parser.ts           ввод формы → чистая модель (валидация, условные поля)
      ramp.repository.ts       отправка на бэкенд (POST)
      ramp.dictionary.ts       справочник(и) этой фичи
      index.ts                 публичный API фичи (createRampFeature)
    crossing/                ПЕРЕХОД — то же по образцу ramp (3 справочника)
    road/                    ДОРОГА — то же (число полос + 2 блока условных полей)

  mock/                    ← заглушка вместо бэкенда (на время разработки)
    mock-dictionaries.ts     данные справочников на русском
    mock-http-client.ts      фейковый клиент: отдаёт справочники, не ходит в сеть

  ui/                      ← экраны (презентационный слой)
    index.html               главная страница (карта + панель формы)
    app.ts                   ГЛАВНАЯ СБОРКА: связывает карту и форму
    map/
      map-screen.ts          карта, выбор точки, кнопка "Добавить"
    attribute-form/
      attribute-form.contract.ts   общий договор формы (render/collect)
      attribute-form-shell.ts      каркас-аккордеон (переключение типов)
      form-helpers.ts              кирпичики: выпадашка, чекбокс, поле
      ramp-form.ts                 форма съезда
      crossing-form.ts             форма перехода
      road-form.ts                 форма дороги
```

## 4. Как данные проходят через приложение

Один общий поток, от клика до готовых данных:

```
карта: клик по точке → координаты
   → кнопка "Добавить" (map-screen.ts отдаёт координаты в app.ts)
   → app.ts открывает панель формы для этой точки
   → волонтёр выбирает тип (аккордеон) и заполняет поля
   → кнопка "Сохранить"
   → форма.collect() собирает сырой ввод (FormInput)
   → [здесь будет] parser превращает в чистую модель (Entity)
   → [здесь будет] repository отправляет на бэкенд
```

Два последних шага пока в заглушке — данные показываются, но не парсятся и не
отправляются. Логика парсинга и отправки уже написана и проверена, просто ещё
не подключена к кнопке (по заданию).

**Важный принцип разделения:** каждый экран знает только свою задачу. Карта не
знает про форму — она просто отдаёт координаты. Форма не знает про сеть — она
просто отдаёт собранный ввод. Связывает их в одном месте `app.ts`. Это защищает
от «спагетти»: поменять одно не значит сломать другое.

## 5. Что делать, когда появится бэкенд

Два изменения, оба маленькие:

**1. Переключить с заглушки на настоящий сервер.**
В файле `src/ui/app.ts` найди строку:

```ts
const http = new MockHttpClient();
```

и замени на:

```ts
import { HttpClient } from "../shared/http/http-client";
const http = new HttpClient({ baseUrl: "https://адрес-вашего-api" });
```

Всё остальное менять не нужно — фичи, формы, справочники этого даже не заметят,
потому что они зависят от общего договора `IHttpClient`, а не от конкретного
клиента.

**2. Подключить отправку.**
В том же `app.ts` найди комментарий `ТОЧКА ПОДКЛЮЧЕНИЯ ОТПРАВКИ` — там уже
написано, какой код туда вставить (по одной строке на каждый тип объекта).

Проверь также реальные адреса эндпоинтов в файлах `*.repository.ts` и
`*.dictionary.ts` каждой фичи (сейчас там заглушки вроде `/ramps`,
`/dictionaries/curb-height`) — поправь под ваш бэкенд.

## 6. Как добавить новый тип объекта

Например, если появится «остановка». Берёшь съезд (`ramp`) за образец:

1. Скопируй папку `src/features/ramp/` → `src/features/stop/`, переименуй файлы.
2. В `stop.entity.ts` опиши поля по таблице из БД (модель + тип ввода формы).
3. В `stop.dictionary.ts` укажи эндпоинты справочников этой сущности.
4. В `stop.parser.ts` повтори образец: числа через `parseInt_`/`parseFloat_`,
   справочники через `variantToId`, условные поля через `if (условие) {...} else null`.
5. Скопируй `src/ui/attribute-form/ramp-form.ts` → `stop-form.ts`, поправь поля.
6. Добавь секцию в список `sections` в `app.ts`.

Общий код в `shared/` трогать не нужно — он уже всё умеет.
