# Город для всех — модуль сбора данных

Приложение для волонтёров: открываешь карту, выбираешь точку (или жмёшь «Я
здесь», чтобы встать на свою GPS-позицию), вносишь данные о дорожном объекте
(съезд / переход / дорога) и отправляешь их на сервер. Собранные данные — основа
базы, по которой потом строятся маршруты для людей с ОВЗ.

Работает как веб-страница и как нативное Android-приложение (через Capacitor) —
код общий, различается только обёртка.

Этот документ объясняет **что внутри** и **как запустить**, с нуля и по-человечески.

Как вносить изменения (issue → ветка → Pull Request) — в [CONTRIBUTING.md](CONTRIBUTING.md).

## 1. Как запустить (быстрый старт)

Нужен установленный **Node.js** (версия 22 или новее). Проверить: `node -v`.
Если Node нет — скачай с https://nodejs.org (бери LTS-версию).

Скачать проект и зайти в его папку:

```bash
git clone https://github.com/Inferrn/gorod-dlya-vseh.git
cd gorod-dlya-vseh
```

Настроить адрес бэкенда (один раз, подробнее — раздел 5):

```bash
cp .env.example .env   # на Windows: copy .env.example .env
```

Дальше две команды в терминале, из папки проекта:

```bash
npm install     # 1) скачать зависимости (один раз). Создаст папку node_modules.
npm run dev     # 2) запустить в режиме разработки
```

После `npm run dev` в терминале появится адрес вроде `http://localhost:5173`.
Открой его в браузере — приложение стартует на экране рейтинга. Точки под
карточкой (или свайп влево/вправо) переключают три вида: таблица, пьедестал,
список участников. Карандаш внизу открывает карту: кликни по любой точке
(или нажми «📍 Я здесь») → внизу появится карточка с координатами → кнопка
«Добавить» → откроется панель ввода данных → «Сохранить» отправит их на бэкенд.
Иконка профиля внизу справа открывает экран подтверждения выхода.

Чтобы остановить — `Ctrl+C` в терминале.

Другие команды:

```bash
npm run build       # проверить типы и собрать готовую версию в dist/ (для веба и для Android)
npm run typecheck   # проверить типы без сборки (полезно перед коммитом)
npm run preview     # локально посмотреть собранный dist/ (как будет выглядеть в проде)
```

## 2. Что уже работает, а что нет

**Работает:**
- Карта (Leaflet), выбор точки кликом или кнопкой «Я здесь» (геолокация).
- Панель ввода с тремя типами объектов (съезд / переход / дорога), один за раз.
- Выпадающие списки наполняются из справочников бэкенда.
- Условные поля: показываются серыми, пока не выполнено условие (например, ширина
  съезда активна только когда отмечен «съезд на проезжую часть»).
- Проверка ввода (число не число, пустое поле) с понятными сообщениями.
- Отправка на бэкенд по кнопке «Сохранить» (`POST` с координатами точки и
  введёнными данными), с индикацией «Отправляем…» и результатом (id записи
  или текст ошибки).
- Android-приложение (APK) — та же веб-страница, упакованная через Capacitor.

**Намеренно НЕ подключено (ждёт следующего этапа):**
- **Адрес по координатам** (обратное геокодирование) — показываем только
  координаты, место под адрес помечено `TODO` в `src/ui/map/map-screen.ts`.
- **Заглушка справочников** (`src/mock/`) больше не используется приложением
  (адрес бэкенда берётся из `.env`), но оставлена в репозитории —
  пригодится, если понадобится погонять UI без доступа к серверу.

## 3. Структура проекта

Проект организован **по фиче, а не по слою**: всё про съезд лежит в одной папке,
всё про переход — в другой. Так модуль самодостаточен, и новую сущность добавляешь
копированием папки, а не размазыванием по десяти местам.

```
src/
  shared/                  ← общий фундамент, используется всеми
    result/                  Result<T,E> — ошибки без исключений
    parsing/                 строка формы → число/bool (с проверками)
    http/                    HttpClient + договор IHttpClient
    dictionary/              DictionaryService — справочники (текст ↔ id, кэш)
    geo/                     GeoPoint — координаты точки (latitude/longitude)

  features/                ← бизнес-логика, по одной папке на тип объекта
    ramp/                    СЪЕЗД — эталонная фича (образец для остальных)
      ramp.entity.ts           модель данных + тип ввода формы
      ramp.parser.ts           ввод формы → чистая модель (валидация, условные поля)
      ramp.repository.ts       отправка на бэкенд (POST, вместе с координатами)
      ramp.dictionary.ts       справочник(и) этой фичи
      index.ts                 публичный API фичи (createRampFeature)
    crossing/                ПЕРЕХОД — то же по образцу ramp (3 справочника)
    road/                    ДОРОГА — то же (число полос + 2 блока условных полей)
    rating/                  РЕЙТИНГ — участники и очки (пока заглушка)
      rating.entity.ts         модель + расстановка мест по очкам
      rating.mock.ts           те же 10 человек и очки, что в макете
      index.ts                 публичный API фичи

  mock/                    ← заглушка вместо бэкенда (не используется по умолчанию,
    mock-dictionaries.ts     оставлена для локальной разработки без сервера)
    mock-http-client.ts

  ui/                      ← экраны (презентационный слой)
    index.html               каркас приложения: три вида рейтинга, карта, выход
    app.ts                   ГЛАВНАЯ СБОРКА: экраны, переходы, адреса, карта + формы
    rating/
      rating-screen.ts         экран рейтинга: три вида, свайп, точки, заголовок
      rating.render.ts         разметка трёх видов (строки, бейджи, пьедестал)
    screens/
      screen-manager.ts        анимированная смена экранов (рейтинг ↔ карта)
      logout-screen.ts         экран подтверждения выхода («шторка» из профиля)
    components/
      toast.ts                 короткие сообщения внизу экрана
    shared/
      dom.ts                   поиск элементов с внятной ошибкой
      format.ts                формат чисел («10 500»)
      motion.ts                счётчик очков и проверка prefers-reduced-motion
    styles/
      tokens.css               палитра и тайминги из макета
      base.css                 сцена, «телефон», экраны, нижняя навигация
      rating.css               таблица / пьедестал / список
      logout.css               экран выхода
      map.css                  карта и панель формы (перенесено из index.html)
      motion.css               все keyframes + «уменьшить движение»
    map/
      map-screen.ts           карта, геолокация, выбор точки, кнопка "Добавить"
    attribute-form/
      attribute-form.contract.ts   общий договор формы (render/collect)
      attribute-form-shell.ts      каркас-аккордеон (переключение типов)
      form-helpers.ts               кирпичики: выпадашка, чекбокс, поле
      ramp-form.ts                  форма съезда
      crossing-form.ts              форма перехода
      road-form.ts                  форма дороги

  vite-env.d.ts            ← типы переменных окружения (VITE_API_BASE_URL)

android/                  ← нативная Android-обёртка (Capacitor), см. раздел 6
assets/, logo.png         ← иконка приложения (исходник для Android-ресурсов)
capacitor.config.ts       ← настройки Android-обёртки (appId, схема WebView)
.env.example              ← образец настроек окружения (копируется в .env)
```

## 4. Как данные проходят через приложение

Один общий поток, от клика до сохранённой записи:

```
карта: клик по точке (или "Я здесь") → координаты
   → кнопка "Добавить" (map-screen.ts отдаёт координаты в app.ts)
   → app.ts открывает панель формы для этой точки
   → волонтёр выбирает тип (аккордеон) и заполняет поля
   → кнопка "Сохранить"
   → форма.collect() собирает сырой ввод (FormInput)
   → parser превращает его в чистую модель (Entity), с проверкой значений
   → repository отправляет Entity + координаты на бэкенд (POST)
   → результат (id записи или ошибка) показывается волонтёру
```

**Важный принцип разделения:** каждый экран знает только свою задачу. Карта не
знает про форму — она просто отдаёт координаты. Форма не знает про сеть — она
просто отдаёт собранный ввод. Связывает их в одном месте `app.ts`. Это защищает
от «спагетти»: поменять одно не значит сломать другое.

## 5. Настройка адреса бэкенда

Адрес API задаётся переменной `VITE_API_BASE_URL` в файле `.env` в корне проекта.
Образец — `.env.example`:

```bash
cp .env.example .env
```

```ini
VITE_API_BASE_URL=http://localhost:8080/api
```

- Для локального бэкенда (репозиторий `gorod-dlya-vseh_back`) оставь
  `http://localhost:8080/api`.
- Адрес общего сервера в репозитории не хранится — спроси его у ответственного
  за проект и впиши в свой `.env`.
- Если `.env` нет или переменная пустая, приложение ходит на
  `http://localhost:8080/api`.
- После изменения `.env` перезапусти `npm run dev`.

**`.env` в git не коммитим** (он в `.gitignore`). Если появляется новая
переменная — добавь её с безопасным примером в `.env.example`.

Остальной код (фичи, формы, справочники) от адреса не зависит — все они
работают через общий договор `IHttpClient`, а не через конкретный клиент.

Реальные пути эндпоинтов и справочников — в файлах `*.repository.ts` и
`*.dictionary.ts` каждой фичи (например, `/ramps`, `/dictionaries/curb-height`).

## 6. Android-приложение (Capacitor)

Веб-код из `dist/` упаковывается в APK через [Capacitor](https://capacitorjs.com/) —
отдельный сервер приложению не нужен, в сеть оно ходит только за тайлами карты
и к API бэкенда (см. `capacitor.config.ts`).

Понадобится **Android SDK** (например, через Android Studio) и путь к нему в
`android/local.properties` (`sdk.dir=...` — файл не в репозитории, создаётся
локально).

```bash
npm run build          # 1) собрать веб-версию в dist/
npx cap sync android   # 2) скопировать dist/ и настройки в android/
```

Адрес бэкенда «зашивается» в APK при `npm run build` из `.env` — перед сборкой
проверь, что там указан нужный сервер, а не `localhost`.

Дальше — либо открыть папку `android/` в Android Studio и собрать/запустить
оттуда, либо через Gradle-обёртку:

```bash
cd android
./gradlew assembleDebug     # соберёт APK в android/app/build/outputs/apk/debug/
```

Подпись релизной сборки настраивается через `android/keystore.properties`
(тоже не в репозитории — содержит пароли от keystore, создаётся локально по
образцу `storeFile=... / storePassword=... / keyAlias=... / keyPassword=...`).

## 7. Как добавить новый тип объекта

Например, если появится «остановка». Берёшь съезд (`ramp`) за образец:

1. Скопируй папку `src/features/ramp/` → `src/features/stop/`, переименуй файлы.
2. В `stop.entity.ts` опиши поля по таблице из БД (модель + тип ввода формы).
3. В `stop.dictionary.ts` укажи эндпоинты справочников этой сущности.
4. В `stop.parser.ts` повтори образец: числа через `parseInt_`/`parseFloat_`,
   справочники через `variantToId`, условные поля через `if (условие) {...} else null`.
5. Скопируй `src/ui/attribute-form/ramp-form.ts` → `stop-form.ts`, поправь поля.
6. Добавь секцию в список `sections` в `app.ts`.

Общий код в `shared/` трогать не нужно — он уже всё умеет.

## 8. Стек

- **TypeScript** — типобезопасность, строгий режим.
- **Vite** — сборка и локальный сервер разработки.
- **Leaflet** — карта, тайлы OSM (зеркало `tile.openstreetmap.de`, доступное без VPN).
- **Capacitor** — упаковка веб-приложения в нативный Android APK.
- Бэкенд (отдельно, репозиторий `gorod-dlya-vseh_back`): Spring Boot,
  PostgreSQL + PostGIS, GraphHopper для маршрутов.

Код прокомментирован на русском для читаемости командой.

## 9. Рейтинг: экраны, переходы и анимации

Четыре экрана из макета живут в одном приложении и связаны переходами.

| Экран | Что это | Как открыть |
|---|---|---|
| 1. Таблица рейтинга | все участники, топ-3 с аватарами, своя строка подсвечена | старт, `#/rating/table` |
| 2. Пьедестал | три лидера колоннами, очки под ними | точка «2», свайп, `#/rating/podium` |
| 3. Рейтинг участников | места 1–10, бейджи и аватары | `#/rating/list` |
| 4. Подтверждение выхода | «шторка» из кнопки профиля | иконка профиля, `#/logout` |

Рейтинг и карта — отдельные экраны. Карта создаётся лениво, только когда её
впервые открыли, поэтому старт приложения не ждёт Leaflet и тайлы.

**Что анимировано** (всё выключается системной настройкой «уменьшить движение»):

- смена экранов рейтинг ↔ карта — сдвиг с лёгким уменьшением уходящего;
- три вида рейтинга — карусель (свайп мышью/пальцем, точки, стрелки клавиатуры);
- заголовок и звезда переезжают вместе с видом;
- строки списка появляются каскадом снизу, очки «набегают» от нуля;
- колонны пьедестала вырастают с пружинкой, места и очки появляются следом;
- выход раскрывается кругом из центра иконки профиля, иконка «дышит»;
- нажатия на нижнюю навигацию дают волну, кнопки — микро-сжатие.

**Где что менять:**

- данные (люди, очки) — `src/features/rating/rating.mock.ts`;
- цвета и тайминги — `src/ui/styles/tokens.css`;
- тексты заголовков видов — `TITLES` в `src/ui/rating/rating-screen.ts`;
- высота колонн пьедестала — `barHeight()` в `src/ui/rating/rating.render.ts`.

Скриншоты всех экранов — в `docs/screenshots/`.
